OAuth 01 - Consent Phishing with Redirect Mismatch

Simulates an OAuth consent phishing attack. The page initiates an OAuth authorization flow with a legitimate-looking provider URL, but the redirect_uri points to the attacker's domain. After "consent" is granted, the callback redirects to the attacker's server which steals the authorization code.

Expected: NavSentinel detects the OAuth flow, flags the redirect_uri mismatch, and elevates the NRS score.

In a real attack, the OAuth URL would point to the legitimate provider (accounts.google.com) but with a redirect_uri controlled by the attacker. The victim sees the real Google consent page but the authorization code is sent to the attacker.
