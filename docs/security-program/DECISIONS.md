# Programme decisions

## SP-D-001: Programme authority is subordinate

The programme registry coordinates security work but does not replace the product roadmap, milestones, live issue state, release gates, or human-action queue.

## SP-D-002: Product profiles stay separate

Release extension, research extension/profile, Proving Ground, optional native companion, and future agent semantics have separate authority and evidence. Seeding enables none of the deferred profiles.

## SP-D-003: Evidence starts conservative

Canonical scenarios remain `UNMODELLED`. Existing fixtures are mapped without inheriting stronger evidence automatically. Only an independent harm oracle can support protection language.

## SP-D-004: Missing supplied registries are reconstructed with provenance

The physical bundle omitted advertised machine-readable capability, evidence-state, backlog, and schema inputs. Stable IDs and semantics were reconstructed only from supplied master documents. Source hashes and missing inputs remain explicit.

## SP-D-005: Reuse issues and keep scenario tasks local

All shared-foundation themes already have live or merged homes. The seed creates zero issues and retains 1,512 scenario tasks in the local registry. A future issue is opened only for a scheduled, bounded slice after another deduplication pass.

## SP-D-006: First bounded vertical is UI-004

`NS-ADV-UI-004` is the preferred first vertical because C-10 has an independent nested-context regression and clear limitations. This does not broaden #557 into general overlay protection or supersede follow-ups #560/#564/#577/#579/#580.
